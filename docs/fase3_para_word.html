3.7.3 Fase III: Desarrollo del Sistema Predictivo

La tercera fase de la investigación se centró en la materialización operativa del motor predictivo mediante la construcción de un sistema integral de información, diseñado para automatizar las decisiones de reabastecimiento en la Pastelería Casserissima. El objetivo fundamental fue transformar las salidas analíticas del modelo de Machine Learning (Random Forest) en alertas gerenciales procesables, garantizando una gestión de inventarios proactiva y minimizando el riesgo de caducidad.

Para cumplir con este propósito, la solución se estructuró bajo una arquitectura lógica Cliente-Servidor (ver Figura X: Arquitectura Lógica). El Backend fue desarrollado en Python utilizando el framework FastAPI, el cual aloja el motor predictivo, expone las interfaces de programación de aplicaciones (API REST) y gestiona la lógica de negocio. Por su parte, el Frontend se construyó con Next.js (React y TypeScript), proporcionando una capa de presentación dinámica orientada a la experiencia de usuario.

La persistencia del historial de predicciones y métricas por producto se garantizó mediante una base de datos relacional construida en SQLite, gestionada a través del ORM SQLAlchemy. La estructura de datos (ver Figura X: Diagrama Entidad-Relación) se compone de entidades transaccionales y de control, permitiendo registrar la trazabilidad exacta desde la transacción de venta histórica hasta el pronóstico de demanda futuro y su respectivo margen de error.

El núcleo decisional del sistema tecnológico radica en la implementación algorítmica del Punto de Reorden Evolutivo, o ROP(t). A diferencia de los enfoques estáticos tradicionales de control de inventarios, la lógica diseñada en esta fase integra directamente el rendimiento predictivo del algoritmo Random Forest. Como se detalla en el Cuadro 4 (Parámetros Matemáticos del Punto de Reorden Evolutivo), el sistema utiliza el Error Absoluto Porcentual Medio (MAPE) como un factor de penalización multiplicativo sobre la desviación estándar de la demanda, y el Error Cuadrático Medio (RMSE) como un margen de seguridad aditivo durante el tiempo de entrega.

Este flujo de cálculo automatizado (ver Figura X: Flujo del ROP Evolutivo) permite que el inventario de seguridad se expanda o se contraiga dinámicamente: si el modelo predictivo detecta una alta volatilidad y aumenta su margen de error empírico, el sistema exige un mayor stock de protección; por el contrario, frente a demandas estables y predicciones precisas, el sistema libera capital inmovilizado.

Finalmente, toda la infraestructura de datos y cálculos matemáticos converge en el tablero de control gerencial (ver Figura X: Captura del Tablero de Control). Esta interfaz gráfica fue diseñada para interpretar en tiempo real los niveles de stock actual contrastados contra el ROP(t) de cada producto, traduciendo la complejidad del modelo en un panel unificado de alertas automáticas escalonadas (Crítico, Alto, Normal, Sin Alerta). Esto permite a la gerencia ejecutar órdenes de producción o compras estrictamente fundamentadas en el comportamiento matemático de la demanda, cumpliendo el objetivo principal del sistema.

Cuadro 4: Parámetros Matemáticos del Punto de Reorden Evolutivo (ROP Dinámico)
Símbolo Parámetro Operativo Descripción y Origen en el Sistema Unidad de Medida
μ Demanda Media Diaria (avg_daily_demand) Promedio histórico de ventas del producto. Obtenido de la tabla sales_transactions en SQLite. Unidades físicas (ej. tortas)
σ Desviación Estándar (demand_std_daily) Mide la volatilidad histórica de la demanda diaria para el producto. Obtenido de la base de datos. Unidades físicas
LT Tiempo de Entrega (lead_time_days) Días que tarda el proveedor o el área de producción en reabastecer el inventario una vez generada la orden. Días
MAPE Error Absoluto Medio Porcentual Métrica de precisión del modelo predictivo (Random Forest). Se usa como factor de penalización: a mayor error predictivo histórico, mayor stock de seguridad (1 + MAPE). Porcentaje (Adimensional)
RMSE Raíz del Error Cuadrático Medio Métrica del modelo predictivo que penaliza grandes desviaciones. Actúa como buffer de seguridad adicional durante el tiempo de entrega. Unidades físicas
z Puntaje Zeta (z_score) Constante estadística derivada de la distribución normal (N~0,1). Para un nivel de servicio deseado del 97%, z = 1.88. Adimensional
SS Inventario de Seguridad (safety_stock) Cojín de inventario calculado dinámicamente como: z * [σ * √(LT)] * (1 + MAPE) + √(LT) * RMSE * 0.5. Unidades físicas
ROP(t) Punto de Reorden Evolutivo Fórmula final del sistema: Demanda esperada en el tiempo de entrega (μ * LT) más el inventario de seguridad dinámico (SS). Unidades físicas
Fuente: Elaboración propia (2026). Basado en Silver, Pyke & Peterson (1998) e implementado en el motor predictivo.
